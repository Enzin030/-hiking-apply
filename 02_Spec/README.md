# 02_Spec

本資料夾放置「臺灣登山申請一站式服務網」的功能規格。

## 編號規則

編號依 **`assets/功能架構圖.png`** 由左到右、由上到下的順序排列，非依撰寫或實作順序
（2026-09-14 使用者裁決）。架構圖是編號的唯一依據——圖改了，編號跟著改。

比照 `115嘉市災管/嘉市災管/02_Spec/README.md` 的同一套慣例：

- **`00_` 前綴給「不是單一 UI 頁面規格」的檔案**：章節層級文件
  （`00_系統功能設計說明.md`）與 Bases 檢視檔。**單頁功能規格一律從 `01` 起算**，
  不與 `00_` 競用。
- **某一頁規格的附屬文件，用「該頁編號＋小寫字母」**。
  目前只有 `06`：架構圖上「申請進度查詢/繳費/異動/取消」是**一個**功能方塊
  （`applySearch.aspx`），底下四份各自成規格，故編為 `06a`–`06d`，**沒有** `06_` 本身。
- **跨模組的設計文件用 `9x_` 編號**，排在頁面規格之後——它不對應任何架構圖方塊。
  目前尚無此類文件。
- **未定案的規格檔加 `_` 前綴**（如 `_12_太魯閣山屋查詢.md`），定案時把前綴拿掉，
  編號與檔名其餘部分不動。判準是**這份文件本身寫完沒有**，不是有沒有未解的待確認項。
  目前無任何一份加前綴。
- **尚未撰寫的檔案先列在下表佔位**，編號預留，補檔時直接用該號，後面不必重編。

架構圖上沒有的功能，**接在架構圖順序之後依序編號**（2026-09-14 使用者裁決），
即 `34` 起：`34_聯絡我們`、`35_山域事故統計儀表板`、`36_快捷選單`。
