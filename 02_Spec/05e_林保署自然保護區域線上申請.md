## 二、步驟 1：日期確認

![日期確認](assets/05e-步驟1-日期確認.png)

  （一般使用者手動操作不太會碰到，自動化要等）

### 2.1 天數與申請目的（2026-10-06 補）

| 可查證事實（正式站程式碼／擷取） | 業務規則（工程師 2026-10-06 口頭；未有書面） |
|---|---|
| 23 區的天數下拉**全部只有 1**（`ForestAreaData.js` 各區 `days: [1]`） | 林保署自己的申請網站**可以多天，依申請目的決定**：民眾只能 1 天；學術研究、祭儀（如豐年祭）等可多天 |
| 第 2 步 `ForestAreaNext()`：已選目的且 `TravelDays > 1` 一律 `ShowSwal(-68)` 擋下，**不看是哪個目的**（`prod-FA001-S02-blank`） | 一站式當初為了統一版面，只採最小天數，**這段要改** |
| 目的的 `limit` 是**人數下限**（原始碼註解「//人數限制」，`TravelPeoples < limit` 時 `ShowSwal(-66)`），與天數無關 | 欄位、元件由 API 即時組出，每條路線（區域）不同 |
| 天數在第 1 步選、目的在第 2 步選——**天數依賴的條件出現在天數之後** | `[待確認]` 可跨日的目的，行程天數上限幾天（區域設定沒有這個欄位，見左欄） |
| 第 1 步天數下拉在前端寫死只有 1（`TravelStep01Days()` 的 `for (let i = 1; i < 2; i++)`） | `[待確認]` -68 的訊息原文（在外部 `js/HSTS/Swal.js`，未擷取） |
| **區域設定 `form_json` 每個目的的 `conf` 帶 `crossday`＝可跨日**（`Func=FormForestAreaList`，2026-10-06 擷取 23 區，`01_Raw_Input/raw/正式站保護區設定.json`） | |
| **可不可跨日是「區域 × 目的」逐一設定**，不是依目的類別一律：學術研究在淡水河紅樹林等 4 區單日、其他 8 區跨日；民眾環境教育 14 區單日、出雲山跨日 | |
| 區域設定的天數相關欄位只有 `accept_min_day`／`accept_max_day`（**收件期間**：進入日前 5～60 天，部分區 7～30、4～60）、`revise_day`、`cancel_day`、`filled_day`；**沒有行程天數上限欄位** | |
| `member_max`（每件人數上限，23 區皆 15）、`area_load`（每日承載量，30～350） | |

彙整（跨日區數／單日區數）：民眾為環境教育之需要 1／14、研究機構或大專院校為學術研究之需要 8／4、
原住民族為傳統文化祭儀之需要 7／4、其他經主管機關認可之特殊需要 11／0、人員入出 3／2、
學術研究需要 2／0、人員進出需要 2／0；逐區明細見原始 JSON。擷取腳本 `scripts/fetch-forest-area-info.py`（唯讀，不送出）。

雛形現況：照正式站只有 1 天。改法待使用者裁示，定案後記入 decisions.md；
`ForestAreaData.js` 是產生檔（R1），多天規則不得手改該檔，要放產生器設定或另立 overlay。

## 五、步驟 5：同意聲明（自然保留區）

![同意聲明](assets/05e-步驟5-同意聲明.png)

標題「自然保留區」，全文為規定說明，要點：
- 可申請目的（許可辦法第 2 條）：原住民族傳統文化祭儀、研究機構學術研究、**民眾環境教育**、其他特殊需要
- 禁止行為十項、罰則（6 個月～5 年有期徒刑、未申請進入罰 3～15 萬）
- **申請流程及規則**：收件自進入日期前 5～60 日；**進入日期前 14 日先抽籤再審查**（抽籤僅限「民眾為環境教育之需要」）；
  每件 15 人為限、每日每件每區姓名與身分證字號不得重複；補件 2 日內一次；進入日期前 4 日起下載許可證；
  6 日前註銷以利遞補；1 年內 3 次以上惡意申請列入禁止名單
- 單一勾選「以上說明，本人業已完全明瞭，並同意確實遵守相關規定。」

## 七、正式站缺陷：同分頁連續申請時 sessionStorage 不清除

**重現**（2026-09-29 實測）：同一分頁先走完警政署入山證到確認頁（未送出），再從林保署區域重新開始申請。

![跨申請帶入人員](assets/05e-缺陷-跨申請帶入人員.png)

- 第 3 步**直接帶入上一張的申請人、領隊與 2 位隊員**（本張只申請 2 人，多出 1 位）
- 第 5 步除了自然保留區規定，**多出警政署的同意聲明區塊**（`apply_05` 只要 sessionStorage 有 `TravelStep02Npa` 就顯示）
- 確認頁**行程摘要整塊空白**：`UnitsGuid` 仍是警政署的 `8F7C09DC…`，路線摘要比對不到

![確認頁摘要空白](assets/05e-缺陷-確認頁摘要空白.png)

原因：第 1 步只覆寫 `MainGuid`／`SecondaryGuid`，不清 `UnitsGuid`、`TravelStep02Npa`、`TravelStep03`。
清空 sessionStorage 後重跑，上述三項都正常。
**風險**：若使用者在此狀態送出，林保署申請可能夾帶警政署的機關代碼與入山資料 `[待確認]`（未送出，無法驗證後端行為）。
**改版建議**：每張申請開始時重設暫存狀態，或暫存以申請為單位隔離。
