## 一之二、導盲磚（無障礙定位點）

依臺灣無障礙網頁開發規範，四個頁面均已在主要區塊起始處設置「:::」定位點並搭配快速鍵：

| 定位點 | 快速鍵 | 區塊 | 放置位置 |
|---|---|---|---|
| `#AU` | **Alt + U** | 上方選單連結區 | `<header>` 起始處（首頁為 `.th-home-body` 起始處） |
| `#AC` | **Alt + C** | 中間主要內容區 | `<main>` 起始處 |
| `#AZ` | **Alt + Z** | 下方選單連結區 | `<footer>` 起始處 |

本站內頁未設置左／右側選單區，故未使用 `Alt + L` / `Alt + R`；
日後若新增側邊選單，請依相同寫法補上（`L` 為左側、`R` 為右側）。

### 標準寫法

```html
<a class="th-accesskey" id="AU" href="#AU" accesskey="U"
   title="快速鍵 Alt+U：上方選單連結區"
   aria-label="上方選單連結區（快速鍵 Alt+U）"><span aria-hidden="true">:::</span></a>
```

各屬性的用意：

- `id` 與 `href` 指向自身，使其同時是「定位點」與「可聚焦的連結」
- `accesskey` 提供快速鍵；`title` 讓滑鼠使用者也看得到快速鍵說明
- **`aria-label` 提供真正朗讀的名稱**，`:::` 以 `aria-hidden="true"` 排除。
  若不這樣處理，螢幕報讀器會唸出「冒號冒號冒號」而非區塊名稱 —— 這是
  多數政府網站的常見缺失，本站已避免。
- 「:::」為**可見**標記，樣式定義於 `components.css` 的 `.th-accesskey`。
  **不得以 `display:none` 或 `visibility:hidden` 隱藏**（會被螢幕報讀器忽略）。
  深色底請加 `.th-accesskey-dark`；照片底請加 `.th-accesskey-hero`（半透明白底確保辨識度）。

### 語言選單（3.1.2 局部語言 / 4.1.2 名稱、角色、值）

頁首「語言」按鈕點擊後展開繁體中文／English／日本語三個選項，採 Disclosure Pattern：

```html
<div class="th-lang" data-lang-menu>
  <button type="button" class="th-utility-btn" id="lang-btn"
          aria-expanded="false" aria-haspopup="true" aria-controls="lang-list">
    <i class="fas fa-globe" aria-hidden="true"></i> 語言
    <i class="fas fa-angle-down" aria-hidden="true"></i>
  </button>
  <ul class="th-lang-menu" id="lang-list" aria-labelledby="lang-btn" hidden>
    <li><a href="#" lang="zh-Hant-TW" aria-current="true">…繁體中文</a></li>
    <li><a href="#" lang="en">…English</a></li>
    <li><a href="#" lang="ja">…日本語</a></li>
  </ul>
</div>
```

重點：

- **每個語系項目都要帶 `lang` 屬性**（`en` / `ja`）。少了它，螢幕報讀器會用中文語音
  硬唸「English」「日本語」，這正是 WCAG 3.1.2 要防的情況。
- `aria-expanded` 隨開合同步；目前語系以 `aria-current="true"` 標示（並顯示勾號，
  不單以顏色表意，符合 1.4.1）。
- 已驗證的鍵盤行為：按鈕上 `↓` 開啟並聚焦第一項、`↑`/`↓` 循環移動、
  `Home`/`End` 跳首尾、`Esc` 關閉並把焦點還給按鈕、`Tab` 移出或點擊外部自動關閉。
- 每個選項高度 36px，符合 2.5.8 目標尺寸。

**待後端**：三個連結目前為 `href="#"`，請改為實際語系網址，
並同步更新 `<html lang>` 與 `aria-current` 的位置。

### 主選單下拉（1.4.13 / 2.1.1 / 4.1.2）

有子項目的主選單改為 `<button aria-expanded aria-haspopup aria-controls>` ＋ `<ul hidden>`，
與語言選單同一套 Disclosure Pattern。桌機滑鼠移入即展開，因此必須滿足 **1.4.13**：

- **可忽略**：按 `Esc` 即關閉（不必移動游標）
- **可停留**：移出按鈕後延遲 220ms 才收合，游標得以移入選單
- **持續**：只有移開或點擊他處才收合，不會自動消失

另有兩個實作重點：

- 桌機滑鼠已因 hover 展開時，再點標題**不會**把它關掉
  （以 `e.detail > 0` 判斷是滑鼠點擊，避免「一點就關」的常見誤操作）；
  鍵盤 Enter／Space（`e.detail === 0`）仍照常切換。
- 同一時間只會有一個下拉展開；子選單超出視窗右緣時自動改為右對齊（`.is-right`）。

鍵盤：`↓` 開啟並聚焦第一項、`↑`/`↓` 循環、`Home`/`End` 跳首尾、`Esc` 關閉並還焦點、
`Tab` 移出自動關閉。窄版（≤900px）改為就地展開的手風琴，不做浮動定位。

### 定位基準

`.th-accesskey` 為 `position: absolute`，其所在區塊必須是定位基準，
已於 CSS 設定 `.th-header`、`.th-main`、`.th-footer`、`.th-home-hero`、`.th-home-main`
為 `position: relative`。新增區塊定位點時請一併加上，否則會跑到錯誤位置。

### 窄版（≤900px）的顯示方式

窄版頁首左右內距縮為 16px，「:::」會與機關標誌重疊，故改為
**視覺隱藏、鍵盤聚焦時再顯示**：

- 以 clip 技法隱藏（`clip-path: inset(50%)` + 1×1px），**不可**用
  `display:none` / `visibility:hidden` —— 那會讓螢幕報讀器完全讀不到，
  等同拿掉導盲磚。
- 元素仍留在無障礙樹與 Tab 順序中；`accesskey`（Alt+U／C／Z）照常可跳轉。
- 鍵盤聚焦時恢復為 24×24px 並加白底，使用者看得到焦點落在哪裡（2.4.7）。
- 已於四頁 390px 下實測：三個定位點皆存在、可聚焦、`aria-label` 與 `accesskey` 完好。

### 焦點順序

每頁 Tab 的前兩個停留點固定為：**① 跳至主要內容（skip link）→ ② `:::` 上方選單連結區**，
四頁皆已驗證一致。

### 瀏覽器操作差異

| 瀏覽器 | 按法 |
|---|---|
| Chrome / Edge（Windows） | `Alt` + 字母 |
| Firefox（Windows） | `Alt` + `Shift` + 字母 |
| Safari / Chrome（macOS） | `Control` + `Option` + 字母 |

建議於「網站導覽」或另闢「無障礙說明」頁面向使用者說明以上按法（見第五節）。

## 四、經判定不適用的項目

**徽章 `.th-badge` 的淺色邊框（約 1.3:1）**
WCAG 1.4.11 適用對象為「識別使用者介面元件與其狀態所必要的視覺資訊」及
「理解內容所必要的圖形」。徽章是**非互動的文字標籤**，其資訊完全由文字承載
（文字對比皆 ≥4.5:1），邊框純屬裝飾，移除後不影響任何資訊的取得，故不適用 1.4.11。

同理，以下皆為裝飾性且已加 `aria-hidden="true"`，不適用非文字對比：
麵包屑箭頭 `.th-crumb i`、輔助列分隔線 `.th-divider`、摘要卡勾選圖示
（狀態文字「已選擇路線／尚未同意申請須知」已明確表達狀態）。

## 五、交付後端時必須補齊的項目

靜態原型無法涵蓋以下準則，請工程師於串接後端時一併實作：

1. **3.3.1 錯誤識別**：驗證失敗時，錯誤訊息須以文字明確指出「哪個欄位、錯在哪裡」，
   並在該欄位加 `aria-invalid="true"` 與 `aria-describedby` 指向錯誤訊息。
2. **3.3.3 錯誤建議**：可預期的輸入錯誤（日期格式、必填未填）須提供修正建議。
3. **3.3.4 錯誤預防**：送出申請前提供確認頁與可回頭修改的機制。
4. **4.1.3 狀態訊息**：查詢完成、送出成功、錯誤摘要等區塊須加
   `role="status"`（一般訊息）或 `role="alert"`（錯誤訊息），
   `news.html` 的筆數區已示範寫法。
5. **1.1.1 動態圖片**：後端輸出的路線圖資、公告附圖須帶有意義的 `alt`；
   純裝飾圖請用 `alt=""`。
6. **2.4.2 網頁標題**：每頁 `<title>` 須隨內容動態產生且唯一。
7. **1.3.5 識別輸入目的**：日後若新增姓名、電話、身分證等個資欄位，
   須加對應的 `autocomplete` 屬性。
8. **無障礙說明頁**：建議新增一頁說明本站的定位點與快速鍵（Alt+U／C／Z）、
   各瀏覽器按法差異，並自頁尾「政策宣告」區加入連結 —— 這是申請無障礙標章時
   檢測單位會看的項目。

## 六、日後維護的硬規定

違反以下任何一條都會讓網站掉出 AA：

1. **顏色一律引用 `tokens.css` 變數**，不得寫死色碼。
   新增顏色前請先算對比：文字 ≥4.5:1、大字（≥24px 或 ≥18.66px 粗體）≥3:1、
   互動元件邊框與焦點框 ≥3:1。
2. **邊框用 `--border-ui`**，不要用 `--slate-200/300`（那兩個只能用在裝飾性分隔線）。
3. **字級一律用 `--fs-*` 變數**，最小 `--fs-xxs` 13px，不得低於 12px。
4. **不得寫 `outline: none` / `outline: 0`** 而不提供替代的焦點指示。
5. **`transition` 不得用 `all` 或無屬性簡寫**，否則焦點框會被動畫化而延遲出現。
6. **每頁一個 `h1`，標題不得跳階**（h1 → h2 → h3），不得為了字體大小而選標題層級。
7. **每個 `<td>` 都要帶 `data-label`**（窄版卡片模式要用），表格要有 `caption` 與 `th scope`。
8. **裝飾性圖示加 `aria-hidden="true"`；純圖示按鈕加 `aria-label`。**
9. **新增自動播放／捲動的內容，必須同時提供暫停控制**（參考跑馬燈的做法）。
10. **新增頁籤請沿用 `data-tabs` 結構**，`js/tabs.js` 已處理 ARIA 與鍵盤，勿自行另寫。
11. **新增頁面必須帶齊三個導盲磚**（`#AU` / `#AC` / `#AZ`），且不可用
    `display:none` 隱藏；區塊本身要設 `position: relative`。
