# 登山一站式專案規格書書寫習慣（專案專用）

本文件記錄「115 登山一站式改版」專案專屬之規格書書寫風格與剪裁標準，補充並限縮通用書寫慣例。

---

## 一、章節與命名慣例

1. **章節標題命名慣例**
   - **文件一級標題（#）**：直接以功能名稱命名（例：`# 最新消息`、`# 違規名單`），不綴「規格」二字。
   - **單一功能規格**：章節採純頁面命名（例：`## 一、列表頁`、`## 二、檢視頁`），不重複前綴功能名稱。
   - **含兩類以上子功能之規格**：為避免指涉混淆，章節一律採「功能-頁面」命名（例：`## 一、最新消息-列表頁`、`## 二、最新消息-檢視頁`、`## 三、歷史消息-列表頁`、`## 四、歷史消息-檢視頁`）。
   - **跨功能全同頁面引用**：章節僅有一句全同引用時，直接單行成句（例：`同最新消息-檢視頁。`），不掛清單符號 `-`。
2. **章節視覺分隔**
   - 主章節（`##`）之間一律使用水平分隔線 `---`，確保 Obsidian 預覽與閱讀時邊界分明。
3. **直述條件，去除抽象標籤前綴**
   - 規則能直述者直接寫（例：`- 非發布期間（發布區間以外）之消息。`），不加「資料篩選：」等抽象分類標籤。
4. **無複雜流程不設「流程與狀態／功能定位」**
   - 純前台展示、查詢類頁面不建「流程與狀態」或「功能定位與入口」小節，直接由第一頁面（`## 一、`）起手。
   - 「流程與狀態」僅保留給有多角色、審核狀態機、附件檢核等複雜業務流程之功能。
5. **無未決事項直接刪除「待確認事項」**
   - 規則已明確者不保留空的「待確認事項」章節或佔位表格。

## 二、頁面與區塊呈現

1. **頁首資訊標準語法**
   - 緊接在頁面標題下方，統一以 Blockquote `>` 標註路徑與實體檔案：
     ```markdown
     > 功能路徑：首頁 > 公布欄 > 最新消息  
     > 頁面網址：news_0.aspx
     ```
2. **區塊採用純清單階層縮排（`-`）**
   - 頁面內部區塊不建立 `###` 次級標題，改以清單符號 `- 區塊名稱` 縮排承接內部元件。
   - 移除無操作性之純展示容器描述（如「頁面標題區」、「區塊標題：純文字」），直接由功能元件或業務清單起手。
3. **跳轉目標簡寫**
   - 操作按鈕與連結直接陳述目標語意（例：`導向歷史消息列表頁`、`導向檢視頁`、`返回最新消息列表頁`），不於句尾括號重複標註目標檔名或 query string。
4. **依真實 DOM / 畫面視覺順序排列元件**
   - 區塊內部文字提示、警語或提醒應依其在 DOM 與畫面上的實際位置依序陳述（例：位於卡片 footer 且在查詢按鈕前方的填寫提醒，應置於按鈕項目前方，不抽離至頂層或外層獨立成項）。
5. **頁籤（Tab/Pill）不誤記為導覽外連**
   - 頁籤列內部之切換標籤（即便名稱為「全區圖」、「步道」或點擊後僅展示圖資），本質仍為頁籤項目（Pill），不可誤寫為另開分頁之超連結。

## 三、贅肉剪裁標準（專案黑名單）

1. **禁寫全站共用規格**
   - 分頁元件（分頁碼、上一頁、下一頁、靠右對齊等）為系統全站標準行為，單頁規格一律不寫。
   - 欄位寬度百分比（如 `欄寬 15%`）屬純前端切版排版細節，規格書不列。
   - 日期標準格式 `YYYY-MM-DD` 屬全站預設，無特殊自訂要求時不重複註明。
2. **純前台頁面不放推測性資料規則**
   - 前台公開展示頁若無精確後端 SQL/Schema 對照，不自創推測性 `## 資料規則`；僅保留純工程控制項 ID 於 `## 內部註記`。
3. **列表純文字欄位不逐條單列**
   - 列表最上方已以「欄位：A、B、C…」列舉全部欄位者，預設純文字顯示之一般欄位一律不逐條單列（禁寫「單位：純文字。」、「日期：純文字。」等廢話）。
   - 僅對具特殊規則、格式加工或互動行為之欄位（如：遮罩、分行、標籤、超連結、點擊行為）展開說明。
   - 欄位帶附加按鈕或標籤時，直述相對位置與行為（例：`檔案名稱：後方依提供之格式並列下載按鈕（如 PDF、ODT），點擊後下載或開啟對應檔案。`），不加「純文字名稱後方」等冗詞。
4. **麵包屑不重複單列**
   - 麵包屑即功能路徑，已於頁首 `> 功能路徑：...` 宣告者，內文一律不重複寫「麵包屑：...」。
5. **進入條件不重複敘述**
   - 來源頁之按鈕／連結已載明「點擊後導向 X」者，目標頁面規格不重複寫「進入條件：點擊…」。
6. **嚴禁杜撰未查證之結果區塊**
   - 頁面初始狀態未呈現結果清單者（如草稿編輯查詢後的草稿列表需特定資料方能觸發，且無公開畫面來源），不得自行猜測、杜撰不存在之欄位或操作子項目；未經查證之推測性區塊整塊拿掉，禁止腦補。
7. **多機關／多頁籤禁止齊頭式概括**
   - 同一頁面下包含多機關（如玉山、太魯閣、雪霸）或多頁籤時，不得粗糙假設各機關欄位按鈕一致。應逐一核對各頁籤的實際 DOM 元素（例：太魯閣全處無官網連結按鈕、各路線版型分為完整／缺路線介紹／僅行程／純圖資四類），忠實記錄真實差異，嚴禁齊頭式套版。
8. **UI 標籤文字忠於畫面與查詢語意**
   - 查詢條件與表單欄位的標籤名稱，必須嚴格依據畫面 DOM 實際文字（例：畫面標籤為「關鍵字」即寫「關鍵字」，不得擅改為「景點名稱」；畫面標籤為「國家公園」即寫「國家公園」，不得擅改為「發布單位」）。
   - 文字輸入框若為關鍵字搜尋或非特定名稱輸入，應明確註明對應目標之模糊查詢（格式：`模糊查詢{具體欄位}`，例：`關鍵字：文字輸入框，模糊查詢景點名稱。`、`檔案名稱：文字輸入框，模糊查詢檔案名稱。`）。
9. **條件呈現按鈕不以大分類一概而論**
   - 頁面若有依特定業務條件呈現之操作按鈕（例：排隊預約情形按鈕），不得逕以廣泛大分類（如「景點分類為宿營地時顯示」）齊頭式概括；若僅部分符合特定業務機制方呈現，直述該具體條件（例：`排隊預約情形：按鈕（僅具排隊預約機制之宿營地顯示）`），不加「非所有…皆有」等贅言。
10. **操作按鈕以實體名稱立項**
    - 操作元件一律直接以按鈕上的實際文字作為項目名稱，格式為：`{按鈕名稱}：按鈕，點擊後...`（例：`點我另開登山申請視窗：按鈕，點擊後另開分頁開啟線上申請頁。`），不外包一層抽象的「按鈕：」分類階層。
11. **隱藏元件（display:none）不列入前台可見規格**
    - 畫面 DOM 原始碼中若以 inline style 或 class 設為 `display:none`（或 `visibility:hidden`）且無前端互動腳本可觸發其顯示者，屬未啟用／已下線項目。前台頁面規格只記載實際可見之元件與項目，不得將隱藏項列為頁面元件；該隱藏控制項資訊僅留存於 `## 內部註記`。
12. **外部網站連結附真實 URL**
    - 規格書中若包含導向外部機關、合作單位或第三方系統之超連結（例：各機關雙語詞彙、中央氣象署天氣預報等），應以 markdown 連結語法掛載真實 URL（例：`[國家公園署-雙語詞彙](https://www.nps.gov.tw/ch/sglarticle/bilingualglossary)`），便於查證與驗收。
