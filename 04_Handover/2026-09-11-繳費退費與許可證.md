# 主題 I　許可證 PDF（**現正失效中**）

### Q61. 前台點「下載許可證」拋 `FileNotFoundException`，是哪裡壞了？

- **答**：**QR code 的輸出路徑寫死在 `C:`，但站台部署在 `D:`。**
  完整因果鏈（每一步皆已驗證）：

  1. `web.config` 設 `pdftype = 1`；`qrcodepath.setpath("1")` 回傳寫死的
     `C:\WEB\Hikenationpark\manasystem\qrcode\`。**實測 `C:\WEB\` 整個不存在**，
     站台實際在 `D:\WEB\nationalpark\HikeNationpark\`（`web.config` 的 `localpath` 也指 D:）。
  2. `apply_3_print.aspx.cs:80` 把 QR code `Save` 到該路徑 → 目錄不存在 → 丟例外。
  3. 該處有 `catch`（`:85-89`）吞掉錯誤，改用備援圖 `~\manasystem\qrcode\chqrcode.png`。
  4. **`D:\...\manasystem\qrcode\` 也不存在，`chqrcode.png` 兩顆硬碟都找不到** → `<img>` 404。
  5. wkhtmltopdf 遇到抓不到的資源 → `ContentNotFoundError`、exit 1、**不產出檔案**。
  6. `apply_3.aspx.cs:2615` 對不存在的檔案取 `FileInfo.Length` → `FileNotFoundException`。

- **出處**：`App_code/qrcodepath.cs:37-56`、`apply_3_print.aspx.cs:64-89`、
  `apply_3.aspx.cs:2582-2626`、`web.config`（`pdftype`／`localpath`）。
- **第 5 步是推論** `[缺口]`：`htmltopdfs.dll` 已編譯，看不到它帶給 wkhtmltopdf 的參數。
  那是 wkhtmltopdf 的預設行為（除非加 `--load-error-handling ignore`），
  且「15 次嘗試零產出」只有這個解釋說得通。
- **與 `divergences.md` D-15 是同一個病根**：D-15 指出 `web.config` 的
  `pdftype = "1"` 而註解寫「1本機，2 59主機，3正式機」，導致
  `apply_1_4.aspx.cs:4434` 的 `pdftype == "3"` 分支不成立。
  **本次根因是同一個開關的另一個受害者**——`qrcodepath.setpath("1")` 走的正是
  「本機」分支，回傳的 `C:\WEB\Hikenationpark\...` 是某台開發機的路徑，
  在這個部署上不存在。凡是以 `pdftype` 分流的程式碼都要一併查。

### Q67. 查詢畫面打哪張表？要有繳費資料才進得去嗎？

- **答**：**只打 `applylist`，與 `campmanagefees` 無關。**

  ```sql
  select * from applylist
  where (serial = @serial or CaseSerial = @serial)
    and teams_name = @teams_name
    and orgid = @org
  ```

  查無資料時 `alert('無查詢資料')` 並 return。
  規費是進頁後才由 `booking` join `node.localmoney`／`fmoney` **即時算**的，
  `campmanagefees` 只在實際繳費時才寫入。
- **出處**：`apply_4.aspx.cs:98-109`（查詢）、`:155-160`（算費用）。

### Q68. 進得去之後，什麼條件才會真的顯示繳費資訊？

- **答**：四關全過才 `isToPay = true`：
  1. `applylist.status` ∈ `0／1／4／9／10／11／12／17`
  2. `booking` 掛在有收費的 `node`（`localmoney` 或 `fmoney` ≠ 0）
  3. 該 `node_id` ＋ 該 `booking_date` 在 `Ballot` 有 `chk = 1` 的公告；
     **未公告且 `node.IsDraw = '1'` → 金額歸零並 `break`，不進繳費畫面**
  4. 算出的 `sumMoney > 0`
  另有前置擋點：`status` 為 `12`（備取）或 `0` 時會檢查
  `booking_bed_yushan` 的配置人數是否等於隊伍人數，不符則 `alert('床位尚未配置完成')`。
- **出處**：`apply_4.aspx.cs:155-240`；擋點在 `:167-179`。

### Q69. 「繳費期限已過期」是怎麼算的？

- **答**：`繳費期限 = MAX(applylist.ballotday, applylist.waitnoticedate) + 3 天`，
  期限 < 今天即 `isOver = true`。兩欄皆空時改顯示「未有通知繳費日期」。
  註解自陳這條規則有漏洞：「如遇需繳費而不需抽籤的宿營地 該規則會被推翻」。

# 主題 M　欄位中文名不可信（**通則，影響所有後續查詢**）

### Q74. schema 的欄位中文名可以當規格看嗎？

- **答**：**不行，只能當線索。** 2026-09-11 一天內遇到四組不符，全部靠實跑或讀程式碼才發現，
  而且**錯的方式都不一樣**：

  | 欄位 | 中文名說的 | 實際 |
  |---|---|---|
  | `apply_teams.member_nation` | 「國家別 本國0 外國1」 | 存中文字串 `中華民國`／`國外` |
  | `applylist.actout` | 離園 | 值域只有 `NULL` 與 **`2`**，全表**無 1** |
  | `campmanagefees.paytype` | 1~4 | 實際 **1~8**，5/6/7/8 無來源 |
  | `campmanagefees.status` | 0 未繳／1 已繳 | 實際還有 **-1、2** |
  | `campmanagefees.refunds` | 退費金額 | **全表無一筆 > 0**，形同未使用 |
  | `applylist.status` | 0~8 | 程式用到 **0/1/4/9/10/11/12/17**，兩套編碼對不起來 |

  最危險的是 `actout`：照中文名寫 `actout = 1` 會**永遠回空集合**，
  看起來像「沒有已出園的資料」而不是「條件寫錯」——**不報錯，只是安靜地錯**。
  `campmanagefees.refunds` 同理，照中文名寫退費條件會完全落空。
- **處置**：實測到的值域已寫進 `03_Schema/_fields/*.md` 的「備註」欄
  （產生器重跑不會覆蓋），並在 Bases 的「所有表結構」視圖直接可見。
- **出處**：各欄位實跑；`applylist.status` 出自 `apply_4.aspx.cs:224-240` 的 switch 與其註解。

### Q75. 用表名或節點名稱做條件要注意什麼？

- **答**：兩件事。
  1. **一個山屋在 `node` 表有多筆。** 排雲有 4 筆 `type = 'H'`：
     `3` 排雲山莊（`chk=2` 部份關閉）、`219` 排雲山莊專3、
     `296` 排雲山莊專3(不收費，費用 0)、`377` 排雲山莊()。
     所以要用 `name LIKE` 而不是寫死 `node_id`。
  2. **但 `LIKE N'%排雲%'` 會抓到 `356` 排雲登山服務中心**，那是 `type = 'G'`
     （登山口／服務中心），與規費無關。**必須同時限 `type = 'H'`。**
- **出處**：`node` 表實跑；`04_Handover/A16.csv:119-122`、`:315`。
