# divergences — 同一條規則在 code 中互相不一致之處

產出日期：2026-09-07　範圍：`05_Prototype/`（純靜態前端雛形，無後端、無 API）

## 讀這份之前必須知道的四件事

**一、沒有後端，所以「前端擋、後端沒擋」這類分歧在本 repo 結構上不存在。**
`apply-3.html` 的送出鍵是 `alert("送出申請")`（`Apply3.jsx:388`），沒有任何提交行為。
本文所有「擋／不擋」都只指前端 UI 的可點擊性。

**二、同名 `.js` 與 `.jsx` 資料檔，live 的是 `.js`。**
九支資料檔各有兩份，32 張產品頁載入的都是 `.js`（`apply-2.html:32-33`、`open.html:33`、
`campsite.html:32-36` 等），`.jsx` 已加 `// DEPRECATED 2026-09-07` 檔頭。
唯一例外是 `TrailLevelData.jsx`，沒有 `.js` 版，由 `open.html:32` 與 `information_6.html:32` 直接載入。
**已用正規化 diff 逐行比對九對檔案，實質內容零差異。** 本文所有出處都指 `.js`。

**三、`assets/components/th-*.js`（Vue 版）不是產品程式碼。**
只被 `_island-test.html` 與 `_stage2-test.html` 兩張測試頁載入（`assets/includes/head.html:78-88`）。
`th-forest-camp-shared.js` 的 `TH_CABIN_DATA` 目前與 React 版逐欄相同，但兩份之間沒有同步機制。

**四、這個 repo 裡有一份「手冊」，而且是逐字照抄的。**
`components/NoticeDetailData.js` 收了正式站 `notice_a1..a10`／`notice_b1..b7` 共 17 頁的全文
（檔頭 `:20`：「逐字照抄，只重組結構，不改寫文字」，產生腳本 `build-notice-detail.py`）。
`components/ConsentData.generated.js` 則是資料庫 `attention` 表的匯出（檔頭 `:18-20`）。
**這兩份是機關的規則原文，不是雛形作者寫的。** 底下凡引用它們的地方，我標成「手冊／匯出資料」；
凡是雛形作者自己打字的常數（`NP_CONSENT`、`SUMMARY_CONFIG`、`CABIN_DATA`、各種硬寫死的文案），
我標成「雛形自撰」。兩者在檔案裡長得一模一樣，這是本份文件最重要的一條分界線。

## D-1　雛形自撰的規則數字，與同 repo 內的手冊全面不符，而且沒有一條被實作

### （三）條文編號來自陣列索引，不是資料裡的 `order`

`Apply2.jsx:49`：`label: \`條文 ${String(index + 1).padStart(2, "0")}\``——用 `map` 的 index。

`total === 0` 這條是典型的「空集合全稱命題為真」，不是刻意設計。

## D-3　同一批路線有兩份資料，同名欄位語意不同、同義欄位值也不同

### （二）`requiresNpa` 的值等於「機關是不是玉山或太魯閣」，不是「要不要入山證」

`RouteData.js:57`。分佈：太魯閣 21 條全 `true`、玉山 18 條全 `true`、雪霸 32 條全 `false`、
林業署 4 條與警政署 2 條全 `false`。與 `OPEN_STATUS_ROWS.needMountainPermit`（`OpenStatusData.js:38`

| 機關 | 一致 | 相反 |
|---|---|---|
| 雪霸 | 32（兩邊皆 `false`） | 0 |
| 玉山 | 17（兩邊皆 `true`） | 1 |
| 太魯閣 | **2**（np-26 南湖大山線、np-27 南湖中央尖，兩邊皆 `true`） | **19** |

### （三）`fId` 在兩份資料是不同的東西

`OPEN_STATUS_ROWS` 479 筆**全部** `fId === cId`（`OpenStatusData.js:98-99`）；
`ROUTE_DATA` 71 筆有 `cId` 者**沒有一筆** `fId === cId`，而是主路線群組 id
——np-22/23/24/25 四條奇萊共用 `fId: "15"`（`RouteData.js:49-50`）。
`Apply1.jsx:10` 會把 `ROUTE_DATA` 版的 `fId` 塞進網址 `?fid=`，下游沒有任何程式讀它。

### （四）「可否申請」與「本日現況」是兩個維度，`ROUTE_DATA.status` 只對應前者

`OPEN_STATUS_ROWS` 有兩個獨立欄位：`canApply`（可申請 450／不可 29）與 `status`（open 446／closed 33）。
`ROUTE_DATA.status`（open 74／closed 3）對應的是 **`canApply`**，不是 `status`。由此產生兩種反直覺情形：

- **奇萊四條（cId 22-25，太管處）**：`canApply:"yes"` 但 `status:"closed"`（`OpenStatusData.js:104-105`），
  在 `ROUTE_DATA` 是 `status:"open"`（`RouteData.js:42`）。
  → `open.html` 顯示綠色「可申請」＋灰色「本日關閉」，`apply-1.html` 顯示「目前可申請」並可直接進入申請。
  全 479 列只有這 4 列出現這個組合。
- **錐麓古道 ×2、清水山**（np-21／np-132／np-35）：`ROUTE_DATA` 是 `status:"closed"` 並帶
  `suspendReason`（`RouteData.js:172`、`:425`），`OPEN_STATUS_ROWS` 同 `cId` 卻是 `canApply:"yes"`
  （`OpenStatusData.js:387-388`、`:368-369`）。
  → `apply-1.html` 出暫停彈窗（`Apply1.jsx:27-71`）擋住，`open.html` 說可以申請。**方向與奇萊那組相反。**

## D-4　`days` 是「天數區間的下限」不是「天數」，`dayMax` 沒有任何程式讀它

`RouteData.js` 每筆有三個天數欄位，以奇萊主、北峰線為例（`:38-40`）：`"days":1, "dayMax":7, "durationLabel":"1-7 天"`。
**77 筆中 53 筆 `days ≠ dayMax`**，極端如奇萊東稜（np-24）`days:1 / dayMax:30`。

| 位置 | 程式 | 把 `days` 當成 |
|---|---|---|
| `Apply1.jsx:87-93` | `"1"` → `x.days === 1`；`"2-3"` → `>=2 && <=3`；`"4+"` → `>=4` | **實際天數（單值）** |
| `Apply1.jsx:324` | `r.durationLabel \|\| …` | 顯示區間原文 |
| `Apply3.jsx:24`、`:95` | 表單預設值、「建議 N 天」 | 建議天數 |
| `Apply3.jsx:131` | `[1..7]` 硬編碼 | 不看 `dayMax` |

後果：在 `apply-1.html` 選「單日」，清單裡出現奇萊東稜，卡片副標寫著「1-30 天」——**同一張卡自己跟自己矛盾**。
反過來選「4 天以上」會篩掉所有 `days < 4` 但 `dayMax` 到 30 的路線（南湖大山線、北二段等）。

`dayMax` 與另外七個欄位在全部程式碼中引用數為 0：
`applyType`、`originalName`、`relatedCIds`、`requiresNpa`、`requiresForestCamp`、
`requiresAttachment`、`requiresSafetyAssessment`。它們並非全為同一值（例如
`requiresAttachment` true 50／false 27、`requiresSafetyAssessment` true 32／false 45），
是有內容的資料被整批忽略。
