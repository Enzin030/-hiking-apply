# 主題 N　`apply_2.aspx` 是查詢頁，規格少了查詢這一段

### Q76. `apply_2.aspx` 這一頁上有什麼？

- **答**：只有六個控制項——`serial`（申請編號）、`sid`（證號）、`nation`（國籍）、
  `nationid`（國別，選「國外」才出現）、`vcode`（圖形驗證碼）、`btnok`。
  標題是 `資料線上異動/取消入園`。
  `.cs` 全檔沒有任何表單欄位處理，`btnok_Click` 驗完驗證碼就查 DB 並
  `window.location.href` 轉走。**它是查詢與分派頁**——民眾用申請編號＋證號查出自己的案件，
  系統依機關與案件狀態把人帶到對應的異動頁。

  > **用詞更正（2026-09-14，使用者指出）**：本份初稿稱它為「登入頁」，那是錯的說法。
  > 這套系統沒有帳號機制，這一步是**查詢**不是登入，叫登入頁會讓人以為有身分驗證。
- **影響 `02_Spec/06d_申請資料異動及取消.md`**：該份把「隊員與領隊互換 `#con_btnSwap`、
  確認修改 `#con_btnModify`、整隊取消 `#con_btnCancelAll`」記在
  「頁面網址：apply_2.aspx」底下。
  **網址沒有標錯**——`apply_2.aspx` 就是這個功能的入口，民眾是從這裡進去的。
  少的是**查詢那一段**：規格直接從異動表單寫起，沒有寫「先輸入申請編號＋證號＋國籍＋驗證碼
  查出案件」這一步，也沒寫查到之後系統會依機關與狀態把人帶去不同的頁

  那幾個控制項（`#con_btnSwap` 等）確實在後面那些頁上，不在 `apply_2.aspx`。

  ① 前面的**查詢步驟**（輸入申請編號＋證號＋國籍＋驗證碼）整段沒寫；

# 主題 O　`taroko_getbednum.cs` ——文件描述與實作不符

### Q82. 這支是不是「太魯閣承載量取得」？

- **答**：**不是。** `rules-vs-code.md` 第七節把「太魯閣：路線與山屋承載量」

  回傳下一個可用號。**承載量數值仍在 `node` 表**，不在這支。
- **這是 `CLAUDE.md` R3 的同型案例第四次**（描述 ≠ 實作）。已回寫該列。
- **出處**：`taroko_getbednum.cs:29`、`:40`、`:145`。

### Q83. 「山屋減量開放（床位減半）」現在生效嗎？

- **答**：**不生效，而且是靜默的。** 該邏輯的開關來自 web.config 兩個 key：
  `open_Bed`（日期門檻）與 `open_Bed_GO`（布林啟用）。
  **這兩個 key 在 `web.config` 裡不存在**——三方確認：(1) `grep open_Bed web.config` 無；
  (2) `<appSettings>`（`:8-122`）沒有 `file=` 外部來源；(3) `web - 複製.config`、
  `web_org.config` 兩份備份也沒有。
  `AppSettings["open_Bed_GO"]` 回 null → `Convert.ToBoolean((string)null)` 回 **false**（不拋錯）；
  `openBed` 同樣是 null，而實際的判斷式是
  `if (roomdates <= Convert.ToDouble(openBed) && openBed_GO)`（`:49`，左運算元先算），
  `Convert.ToDouble((string)null)` 回 **0** 也不拋錯，所以整條恆為 false。
  減半那整段從未執行，且不報錯、無 log。
- **但這個安靜是「鍵不存在」才有的**：若哪天有人把這兩個 key 加進 web.config 卻留成**空字串**，
  `Convert.ToBoolean("")` 會拋 `FormatException`，`Convert.ToDouble("")` 同樣會拋——
  從「永遠不執行」變成「整頁掛掉」。補設定時要給真值，不能給空值。
- **同型**：與「寫死的封園日期過期了不報錯」同一類，但成因不同——這裡是**設定鍵缺席**。
- **出處**：`taroko_getbednum.cs:25-26`、`:49`、`:63`、`:84`、`:154`；`web.config:8-122`。

### Q85. 這支服務誰？

### Q86. 金額怎麼算？費率取自哪裡？

- **答**：費率**不在 `RuleSet`，在 `node` 表且 `node_id` 寫死為 `3`**
  （`sPayNode = "3"`），取兩個欄位：`fmoney`（外籍每人）與 `localmoney`（本國每人）。
  再依 `apply_teams.member_nation` 分「中華民國」／「國外」計數，公式：

  ```
  應繳 = (外籍人數 × fmoney + 本國人數 × localmoney) × (床位筆數 ÷ 總人數) + 10
  ```

  `+10` 是寫死的虛擬帳號手續費（`iAccount = 10`）。
  若 `床位筆數 % 總人數 != 0` 就回 `ERROR,床位繳費資料異常`——
  也就是**繳費前每個人的每一晚床位都必須配齊**，否則產不出繳費碼。
  另有一個 `iCharge = 10` 宣告後未使用。
- **順帶結清一題**：09-11 補記指出「排雲山莊」在 `node` 有三筆同名（`3`、`296`、`377`）。
  **繳費一律取 `node_id=3` 的費率**，另兩筆不參與計價（`296` 費用為 0）。
- **待 DB**：`node_id=3` 的 `fmoney`／`localmoney` 現值未查（第 19 題）。
- **出處**：`FiscApi.cs:66-146`。

# 主題 Q　`taroko_applydateOpenForeign.cs` ——星期別規則**有**實作

### Q88. 太魯閣外籍提前的「非假日（週一至週四）」擋不擋？

- **答**：**擋，而且寫在 code 裡。** `isHolidaySet()` 直接比對
  `DayOfWeek`，命中 `Friday`／`Saturday`／`Sunday` 就排除該日；
  非週五六日再查 `HolidaySet`（同 `OrgID`）判國定假日；
  若該日又出現在 `HolidaySetForeign`，則**回開**（20230523 加的例外表）。
  機關原文說「週一至週四」，等價於排除週五六日——**這條是一致**。
- **這推翻了一句既有通則**：`rules-vs-code.md` 統計段寫
  「所有帶**星期別**的規則，一條都沒有實作」。至少這一條有。
  該句應改為「`RuleSet` 承載不了星期別，**機關層級**的星期別規則沒有實作；
  路線／流程層級另有硬編碼的星期別判斷」。已回寫。
- **仍未找到**：原文另一條「同一年度僅能申請 1 次」在本檔沒有實作，需查申請表端。
- **出處**：`taroko_applydateOpenForeign.cs:62-95`。
