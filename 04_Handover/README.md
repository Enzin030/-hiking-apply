## ⚠ 資料位階警語（2026-09-16 使用者裁決）

**這批分析的 code 與 DB 都在測試機上，所以裡面的「規則值」不等於正式機的規則值。**

- `rules-vs-code.md` 的 94 列判定與分類統計（一致 17／不一致 23／沒實作 25／待查 27／
  統計口徑 2）是**測試機 DB 回填**的結果。**測試機 DB 的規則值與正式機不必然相同**，
  所以那些分類數字不可直接當成正式系統的現況陳述；要下結論前需以正式機資料重新確認。
- 同理，`S1結果.csv`／`S2結果.csv` 與 2026-09-11 補記中標「實測」者，皆為測試機實測。
- **`A*.csv`、`S*結果.csv` 與 `03_Schema/_fields/` 的欄位樣本是 DB 歷史紀錄，不是規格。**
  其中出現舊路線名（如「玉山主（西）峰單日往返路線」，正式站現為「玉山線單日往返路線」）
  屬正常——歷史申請紀錄本來就存著當時的名稱。**這一類不修正**，但引用時不可當成現行規則。
  實測帶舊路線名的檔：`A13.csv`（2 處）、`A2.csv`、`A3.csv`、`S2結果.csv`（各新舊並存）、
  `附錄-雛形與正式系統落差_參考用.md`、`rules-vs-code.md`（2 處），以及
  `03_Schema/_fields/applylist__team_check1.md`、`applylist_for__team_check1.md`
  （那兩支是**欄位中文名**，已於檔頭加註）。
  **CSV 不加檔頭註解**——那會多出一列非資料內容、破壞欄位解析；以本節作為它們的註記。

同源的教訓見 `02_Spec/README.md`「溯源慣例」：兩站（`service.skyeyes.tw` 測試站、
`hike.taiwan.gov.tw` 正式站）的頁面長得一樣、網址結構也一樣，看畫面分不出來，
所以任何從外部擷取的內容都要記「哪一台、哪一天」。
