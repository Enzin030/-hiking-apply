# 側邊導覽列 (Sidebar Navigation) UI/UX 優化報告

## 1. 原系統導覽列痛點分析 (Pain Points Analysis)

綜合您提供的 HTML 結構與先前畫面，現有側邊欄存在以下 UX 致命傷：

1. **資訊架構 (Information Architecture, IA) 扁平且過載**：
   - 僅分為「系統管理 (28項)」與「入園管理 (23項)」兩個極度龐大的主節點。
   - 所有功能如流水帳般平鋪直敘，無次級分類（Sub-categories）。這導致使用者必須在長達超過 50 個項目的列表中靠眼球「地毯式搜索」，認知負荷 (Cognitive Load) 極高。
2. **缺乏視覺層次與輔助 (Lack of Visual Hierarchy)**：
   - 採用舊式 TreeView (`+ / -` 展開結構)，視覺上缺乏 Icon 幫助大腦快速辨識功能意圖。
   - 項目間距過小，點擊區域 (Click Target) 不足，易造成誤觸。
3. **命名冗長且具重複性 (Redundant Naming)**：
   - 多個項目帶有重複前綴（例如：「雪霸入園申請審核」、「玉管處入園資料審核」、「太管處入園資料審核」），增加閱讀時間。
   - 許多維護與設定功能散落各處（如：KML、推播、Email設定），未能模組化歸類。

## 2. 優化策略與架構重組 (Optimization Strategy & IA Restructuring)

為落實「極簡美學」與「開發者/使用者皆友善」，進行以下改造：

### 2.1 導覽列 UI 介面設計規範 (UI Design Principles)

- **手風琴折疊選單 (Accordion Menu)**：捨棄舊時代的樹狀圖，改採平滑展開的 Accordion 設計。同一時間建議只展開 1~2 個主分類，保持畫面清爽。
- **圖示化 (Iconography)**：為「主類別」配置 FontAwesome 圖示，子項目則採實心或空心圓點輔助，或利用適當的左側縮排 (Padding-left) 取代圖示，營造乾淨俐落感。
- **Hover 與 Active 狀態反饋**：
  - Hover 時給予極淡的字體高亮或背景色。
  - 當前所在頁面 (Active) 的左側給予一條粗細適中的 Primary Color 提示線 (`border-left`)。

### 2.2 資訊架構 (IA) 重組建議方案

將原本龐大的 2 巨頭分類，拆解為 **5 大模組 (Modules)**，並將園區特定的功能收納至統一入口或次級選單中。

#### 重組後的新導覽列架構 (New IA Tree)

1. 📊 **營運總覽 (Dashboard)**
   - 營運儀表板 (新增與保留首頁特性)
2. 📝 **入園審查與管理 (Entry Review)**
   - _審核與發證_：雪霸入園申請審核、玉管處入園資料審核、太管處入園資料審核、雪霸許可證列印、許可證注意事項維護
   - _名額查詢與抽籤_：外籍保留名額查詢、活動保留名額查詢、民眾抽籤、民眾抽籤(單日往返路線)、宿營地抽籤及公告、宿營地抽籤結果維護
   - _宿營資源_：雪霸宿營地查詢、宿營地床位重排
3. 👮 **現場查核與違規 (Inspection & Violations)**
   - _入園查核_：查核實際入園情形、查核實際入園情形(太管)、查核實際入園情形(雪霸)、排雲山莊查核、排雲山莊供水紀錄
   - _違規與事故_：違規事項管理、違規案件(黑名單)維護、山域事故、回傳座標列表
4. ⚙️ **營運規則設定 (Business Rules)**
   - _路線與地圖_：規則設定、節點管理、其他路線類別設定、禁止進出登山口設定、KML維護管理、KML路徑關聯管理
   - _期間與管制_：假日設定、太魯閣非上班日設定、雪季設定、花季設定、禁止外籍提前申請設定、禁止申請時間(抽籤時間)、太魯閣候補關閉設定
   - _國別與退費_：國別設定、可申請退費日期設定
5. 🛠️ **系統與基礎模組 (System & Comm.)**
   - _組織與權限_：單位管理、角色管理、帳號管理
   - _通訊設定_：電子郵件設定、Email簡訊類別維護、Email範例維護、emailNotifyMaintain
   - _App推播_：推播類別維護、推播維護、推播裝置清單
   - _內容與多媒體_：注意事項、太魯閣審核回覆範本、片語詞庫、登山安全影片

## 3. 未來各頁面通用 UI/UX 優化指南 (Universal UI/UX Guidelines for Future Pages)

為了確保日後產出的任一頁面皆符合本次專案的高標準，訂定以下通用指南：

1. **表單頁面 (Forms & Settings)**：
   - **單欄或雙欄原則**：避免滿版複雜表單，盡量以卡片 (Card) 包覆表單群組。
   - **明確的必填標示**：取代突兀的紅星號 (`*`)，可於 Placeholder 或 Label 旁以極淡灰色標記 `(必填)`。
2. **列表頁面 (Data Grids)**：
   - 延續儀表板的設計原則：無縱向分隔線、靠右對齊數值、提供分頁 (Pagination) 與每頁顯示筆數切換，過濾操作 (Filter) 固定於表格右上方或列表頂端區域。
3. **對話框與警示 (Modals & Alerts)**：
   - **非破壞性操作**（如儲存成功），採用右下角或頂部出現的 Toast 輕提示，3秒後自動消失。
   - **破壞性操作**（如刪除帳號、強制退件），必須彈出 Modal (對話框) 進行二次確認，且「取消」按鈕樣式須明顯區別於「確認危險操作」按鈕（例如 confirmation btn 使用 `--danger` 色系）。
